# MVP-A (эмуляторы): план реализации

> **Для агентов-исполнителей:** обязательный суб-скилл — superpowers:subagent-driven-development (рекомендуется) или superpowers:executing-plans; задачи выполняются по порядку. Шаги размечены чекбоксами (`- [ ]`).

**Цель:** на эмуляторах API 26/29/31/33/35/36/37 доказать, что каждое считывание агента, каждое действие Device Owner и цепочка «агент → MQTT 5 → Mosquitto» работают как в протоколе; заполнить матрицу `0-mvp-feasibility.md` и выпустить ТЗ v0.3.

**Архитектура:** монорепо Gradle без convention-плагинов. `shared:kernel` и `shared:protocol` (KMP) и агент из 4 модулей (`domain` KMP, `data`/`presentation`/`app` Android) по Clean Architecture с TDD. Отладочный экран Capability Lab (MVI по канону white-label) показывает каждую проверку матрицы и экспортирует JSON-отчёт. Стенд: docker compose с Mosquitto 2.1 (TLS + DynSec + persistence). Серверные спайки S1–S3 — одноразовый модуль `spikes:broker-load`.

**Стек:** Kotlin 2.4.21 · AGP 9.5.1 (встроенный Kotlin) · Gradle 9.8.2 · Koin 4.2.2 · HiveMQ MQTT Client 1.4.2 · OkHttp 5.5.1 · Room 2.8.5 + KSP 2.3.13 · Jetpack Compose (BOM 2026.09.00) · kotlinx-serialization 1.12.0 · coroutines 1.11.0 · Kover 0.9.11 · detekt 2.0.0-alpha.6 · Konsist 0.18.1 · JUnit 4 + **Truth 1.4.5** (все модули) · Robolectric 4.17 · MockK 1.14.11 · Turbine 1.2.1 · Mosquitto 2.1.2.

**Спецификация:** `docs/stages/0-mvp.md`, `docs/stages/0-mvp-feasibility.md`, `docs/architecture.md` (разд. 1, 3, 4, 6, 7, 9), `TZ_RestoFleet.md` разд. 7 (протокол), 6.1 (FR-AG).

## Решения (согласованы 06.11.2026)

1. **detekt 2.0.0-alpha.6** вместо стабильного 1.23.8: стабильная ветка не работает с Kotlin 2.4. Альтернатива — откатиться на Kotlin 2.0.x, это хуже.
2. Тип результата в `shared:kernel` называется **`Outcome<T, E>`**, а не `Result`: так он не затеняет `kotlin.Result`.
3. Канон MVI (`MviStore`, `Reducer`, `BaseMviViewModel`) кладётся в **`console:core:mvi`** уже в MVP (архитектура разд. 5: агент подключает `core:mvi`).
4. Архитектурные тесты Konsist лежат в отдельном JVM-модуле **`:konsist-tests`**, а не в одном из продуктовых модулей.
5. Спайки S1–S3 — модуль **`:spikes:broker-load`**, а не `server/simulator`: настоящий симулятор пишется в К, спайк одноразовый. Модуль исключён из Kover.
6. Тестовое приложение **`:tools:dummy-waiter`** (`ru.restofleet.dummy.waiter`) нужно для R7/R12/C2/D3 (версии, обновление, запуск, тихая установка). APK раздаёт `apk-host` (nginx с сертификатом стенда) в compose.
7. **Mokkery в MVP не подключаем:** в domain-тестах — ручные фейки портов (архитектура разд. 6), MockK — только в Android-модулях.
8. Учётка MQTT на эмуляторе задаётся через `adb shell am broadcast` в debug-ресивер, защищённый `android.permission.DUMP` (его имеет только shell). Учётка хранится через Keystore — это сразу проверка L5.
9. Уже выполненные `cmdId` хранятся персистентно (последние 200). Это защита от повторного исполнения при повторной доставке QoS 1; без неё `reboot` может уйти в цикл перезагрузок.
10. Если `expiresAt` команды уже прошёл, агент её не исполняет и отвечает `failed` с `reason: "expired"` (уточнение P2 со стороны агента).

## Global Constraints

- Весь код на Kotlin; Clean Architecture: `domain` не импортирует `android.*`, `androidx.*`, `io.ktor.*`, `org.jetbrains.exposed.*`, `kotlinx.serialization.*`, `org.koin.*`, `com.hivemq.*`, `okhttp3.*`.
- Без convention-плагинов и `build-logic`: свой `build.gradle.kts` у модуля; все версии, плагины, `compileSdk/minSdk/targetSdk/jvmTarget` — только в `gradle/libs.versions.toml`.
- Koin — только constructor injection; `KoinComponent` и `get()` — только в composition root (`agent:app`).
- Kover-гейт: проект ≥ 80 %, `shared:*`, `agent:domain`, `console:core:mvi` ≥ 90 %; чистые функции `agent:data/platform` — 100 % веток. Исключения: `@Composable`, `*Module*`, `di/`, `*Activity`, `*Service`, `*Receiver`, `*Worker`, `BuildConfig`, `ComposableSingletons*`, `:spikes:*`, `:tools:*`.
- TDD: тест пишется и падает до реализации.
- Пакеты: `ru.restofleet.<part>.<layer>`; applicationId агента — `ru.restofleet.agent`; DO-компонент — `ru.restofleet.agent/.AdminReceiver`.
- Протокол: префикс `rf/v1/`, JSON UTF-8, время — epoch millis; keepalive 30 с (P7), `Clean Start=false`, Session Expiry 86 400 с, clientId = deviceId (P6), LWT retained QoS 1 с `connId` (P3).
- Сертификаты: SAN `localhost`, `127.0.0.1`, `10.0.2.2`, `mosquitto`, `apk-host`, IP машины в LAN. Ключ CA — только в `deploy/certs/out/` (в `.gitignore`).
- Требования, получившие ❌ в матрице, не реализуются дальше.
- **Тесты: JUnit 4 + Google Truth** (`assertThat(x).isEqualTo(y)`), как в white-label-android; `kotlin.test`-ассерты не используются. Truth работает только на JVM, поэтому тесты KMP-модулей лежат в `src/jvmTest` (код — в `commonMain`, покрытие то же). Исключения — `assertFailsWith`/`assertThrows` для проверки исключений.
- **Git:** ветка на этап. `main` — только документация и завершённые этапы; MVP ведётся в `stage/0-mvp`, курсовая — в `stage/1-coursework`, практика — в `stage/2-practice`, диплом — в `stage/3-diploma`. Ветка следующего этапа создаётся от `main` после слияния предыдущего; на слиянии ставится тег (`mvp-a`, `mvp-b`, `coursework`, …).
- Коммит после каждой задачи, Conventional Commits, **без трейлеров атрибуции** (`Co-Authored-By` и т. п.).
- **Device Owner проверяется на эмуляторах**: DO-AVD для API 26, 35, 36 и 37 (по столбцам матрицы), D7 (QR) — попытка на образе с мастером настройки (см. 4.1). На реальном планшете в MVP-B остаётся только то, что на эмуляторе проверить нельзя.

## Review Focus

1. **Неизвестные поля и значения в JSON** (новая версия бэкенда добавила поле или код ошибки) → агент не падает: `ignoreUnknownKeys`, коды ошибок проб — `String` в DTO, неизвестный код → `ProbeError.OTHER`. Тесты — задачи 0.4 и 3.2.
2. **Коллектор бросает исключение или зависает** (`SecurityException` после отзыва разрешения, датчик не отвечает) → остальные считывания и Capability Lab работают, строка помечается ❌/⚠️ с причиной. Тесты — задачи 1.3 и 1.4.
3. **deviceId с `/`, `+`, `#`, пробелом или пустой** → построение топика отклоняется, а не подписывает на чужие топики. Тест — задача 0.3.
4. **Повторная доставка той же команды** (QoS 1 после реконнекта или перезагрузки) → команда исполняется один раз; повтор игнорируется, потому что исходный ответ уже отправлен или лежит в outbox. Тест — задача 3.4.
5. **Переполнение буфера и обрыв во время досылки** (1 ч офлайна, >10 000 записей, брокер падает посреди flush) → FIFO-вытеснение самых старых, порядок сохраняется, неотправленное не теряется. Тесты — задачи 3.3 и 3.4.
