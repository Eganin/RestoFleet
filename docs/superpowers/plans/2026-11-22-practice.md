## Общие правила (для всех вех)

- **Код.** Kotlin, Clean Architecture. Domain не зависит от Android, Ktor, Exposed, HiveMQ, kotlinx-serialization, Koin, Decompose и Compose. Koin — только через конструктор; `get()`/`inject()` допустимы лишь в composition root: `server:app`, `Application.module`, `console:root`, `console:app-*`, `<f>-component/di`. Convention-плагинов нет: у каждого модуля свой `build.gradle.kts`, все версии — в `gradle/libs.versions.toml`.
- **Консоль.** Модули:
  - `console/core/{common, mvi, decompose, network, storage, designsystem, ui, testing}`;
  - `console/root`, `console/app-android`, `console/app-desktop`;
  - `console/feature/<f>/{<f>-domain, <f>-data, <f>-ui, <f>-component}`.

  Пакеты — `ru.restofleet.console.core.<m>` и `ru.restofleet.console.feature.<f>.{domain,data,ui,component}`. Модули KMP с таргетами `android` и `jvm`, iOS нет (реш. 429). Presentation — канон MVI (`architecture.md`, разд. 5). Фича не зависит от другой фичи: экраны связывает родитель через `Output` и фабрики дочерних компонентов.
- **TDD.** Тест пишется и падает раньше реализации. Инструменты:
  - JUnit 4 и Truth; тесты KMP — в `jvmTest`;
  - в domain — ручные фейки портов, MockK — только в JVM- и Android-модулях;
  - Turbine для Flow, Ktor `testApplication` (сервер) и `MockEngine` (клиент консоли), Testcontainers для PostgreSQL и Mosquitto.

  `RuleEngine`, `ProbeAggregator`, `IncidentClassifier` и `IncidentReconciler` покрываются **табличными** тестами: каждая строка — вход, прежнее состояние и ожидаемый результат. Обязательны пограничные значения порогов и каждый случай S8.
- **Покрытие.** Новый модуль подключается к корневому Kover (`kover(projects.…)`) и своему варианту `ci` (у KMP — `add("jvm")`). Пороги: серверный domain ≥ 90 %; консоль — `-domain` ≥ 90 %, `-ui` ≥ 85 %, `-data`, `core:network` и `core:storage` ≥ 80 %; проект ≥ 80 %. `-component` и `app-*` идут только в общий агрегат (реш. 429).
- **Гейт перед каждым коммитом:** `./gradlew build detekt koverVerifyCi :konsist-tests:test --continue`, нужен **rc = 0**. Запускать фоном, Docker должен работать. Коммит — только после rc = 0. Ошибку KSP Room лечит `:agent:data:kspDebugKotlin --rerun` (handoff).
- **Коммиты:** Conventional Commits, **без** `Co-Authored-By` и `Generated with`. В индекс — только явные пути (`git add <пути>`); `git add -A`, `git add .`, `stash`, `checkout` и `switch` чужих веток запрещены. WIP-коммит — только при зелёном гейте.
- **Секреты:**
  - не выводить и не коммитить `deploy/.env`, `deploy/out/`, `deploy/certs/out/`, `deploy/apk/`;
  - пароли передавать через файлы и stdin;
  - токены (access, refresh, код регистрации) не попадают в логи, URL, `toString` и снимки экрана; логирование Ktor-клиента есть только в debug и вырезает `Authorization`;
  - утечку проверять только числом.
- **Konsist:**
  - серверные правила расширяются в `ArchitectureTest.kt` (поток A);
  - правила консоли — в новом `ConsoleArchitectureTest.kt` (поток B): `-domain` без фреймворков; `-ui` без `-data`, Decompose, Ktor и Koin; ViewModel зависит только от use cases; нет импортов чужой фичи; `KoinComponent` только в composition root;
  - текстовая проверка `build.gradle.kts` фич: нет `projects.console.feature.<другая>`.
- **Данные предприятия.** Компания называется ООО «…». Факты, которых нет, помечаются `[[ДАННЫЕ ПРЕДПРИЯТИЯ: …]]`. О внутренних сервисах ничего не выдумывать. Корпоративные репозитории из `~/StudioProjects` не читать и не цитировать: репозиторий публичный (реш. 402). В коде и конфигах цели проверок и package name — только значения-примеры (реш. 425).
- **Отчётность.**
  - В отчёте своего потока ведётся «Прогресс», чтобы работу можно было продолжить после обрыва API: A — `docs/reports/2-practice/P-backend.md`, B — `P-console.md`, C — `P-analysis.md`.
  - В конце вехи — метрики (тесты, покрытие), отклонения, что не проверено.
  - Решения пишутся в `decisions.md`, в раздел своего потока, номера — из своего диапазона (реш. 407).
  - `docs/handoff.md` обновляет только поток A и оркестратор.
- **Окружение:** macOS, `python3 -I`, команды `timeout` нет. Свободного места ≥ 15 ГБ (`df -h .` перед тяжёлыми шагами); у каждого worktree свой `build/` ≈ 3–5 ГБ. Эмулятор — только `rf-api36`, `-no-window -no-audio -no-boot-anim -port 5600`.
- **Неоднозначность** закрывается Ruling, вопросы пользователю не задаются. Остановка — только перед необратимым или небезопасным шагом.

```
A: ПМ1 ─┬─ ПМ2 ── ПМ3 ── ПМ4 ── ПМ5 ─┐
B:      └─ ПМ6 ── ПМ7 ── ПМ8 ────────┼─ слияние ── ПМ10 ревью ── ПМ11 валидация ── ПМ12 исправления ── ПМ13 отчёт
C: ПМ9 ──────────────────────────────┘
```

**Протокол слияния.**
- Сливает оркестратор: в основной копии `git merge --no-ff stage/2-practice-console` (и `-docs`).
- Слияние делается только между вехами A, когда A не запущен. После слияния — гейт; при rc ≠ 0 исправляет владелец сломанного кода.
- B может подтянуть свежий контракт сам: `git merge stage/2-practice` в своём worktree. Rebase запрещён.
- Плановые слияния: B — после ПМ6 (по возможности) и после ПМ8; C — после ПМ9.

  - дедупликация по `(rule, device, target)`: повторный вход при открытой тревоге ничего не меняет — так поглощаются повторы событий после перезапуска агента;

  - use cases `ListAlerts(filter, includeSuppressed=false)`, `AcknowledgeAlert`, `ResolveAlert(comment обязателен, 1..500)`, `GetSummary`.

  **Табличные тесты `RuleEngineTest`:**
  - R-01: `offline` и `online`, offline с чужим `connId` игнорируется ещё в `HandleStatus`;
  - R-02: 19, 20 и 21 % при `charging` false/true, `exit`;
  - R-03: `thermal` MODERATE и SEVERE, 45,0 и 45,1 °C;
  - R-04: `fg_absent`, затем `fg_changed` на отслеживаемое приложение;
  - R-05: `probe_state` down/up по цели;
  - R-06: 499/500 МБ на входе, 599/600 МБ на выходе (гистерезис 100 МБ);
  - жизненный цикл: ack → resolve; повторный resolve → `Conflict`; resolve без комментария → `Validation`;
  - ручное закрытие при сохранившемся условии не открывает тревогу заново.
- [x] **2.2 Встраивание в приём.** `IngestBatch` и `HandleStatus` вызывают доменный сервис `AlertProcessor` в **той же транзакции** (реш. 414): ack после commit покрывает и тревоги. События `EventBus` публикуются после commit. Тест: повторная доставка пакета не создаёт дублей.
- [x] **2.3 Data.** `V2__alerts.sql`:

  Репозитории Exposed, `SharedFlowEventBus` (in-process, `extraBufferCapacity` и `DROP_OLDEST` + счётчик), тесты Testcontainers.
- [x] **2.4 API:**

  - у `GET /devices` новые параметры `q` (имя, код и название ресторана, модель; `ILIKE` с экранированием `%_`), `version` (версия агента, реш. 424) и `problems=true` (есть открытая неподавленная тревога);

  - тесты `testApplication`: 401, 400, 404, 409.
- [x] **2.5** Гейт → коммит. `P-backend.md`.

## ПМ3. Инциденты, WebSocket, сессии (поток A, ≈ 9 ч)

- [x] **3.1 Domain `incident/`** (TDD, табличные тесты, ≥ 90 %):
