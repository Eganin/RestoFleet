## 4. Архитектура этапа

### 4.1 Агент: Device Owner
- `agent:data/deviceadmin` (адаптеры из MVP) → use cases `RebootDevice`, `InstallPackage` (URL + SHA-256), `EnterKiosk/ExitKiosk` (lock task с Chrome на адресе кухонной станции), `LaunchApp` без участия пользователя, `GrantSelfPermissions`.
- `Capabilities` переключается в режим DO автоматически (`isDeviceOwnerApp`); в обычном режиме эти команды возвращают `unsupported: requires_device_owner` (S9).
- Тень: рабочие часы ресторана, режим киоска, список разрешённых приложений (AG-52).
- QR-регистрация (AG-11): консоль показывает QR с адресом и кодом, агент сканирует. Регистрация DO по QR после сброса — опционально.

### 4.2 Бэкенд: новые пакеты domain
| Пакет | Содержимое |
|---|---|
| profile | `ParamProfile` (global / restaurant / role / device), `ResolveDesired` = global ⊕ restaurant ⊕ role ⊕ device (`shared:shadow` merge), `AppliedReport` («X из Y») |
| rule | редактируемые правила (условие, порог, длительность, область), учёт рабочих часов ресторана; R-10 (p95 > 2 с за 5 мин), R-11 (устаревшая версия), R-12 (delta > 10 мин) |
| access | роли admin / support / observer, проверка принадлежности ресторанов наблюдателю, подтверждение опасных команд |
| audit | `AuditRecord`, запись всех изменяющих действий пользователей |
| availability / report | хронология доступности целей по ресторанам, отчёты, CSV-выгрузка отчётов |
| restaurant | + рабочие часы (`work_hours jsonb`), валидация полей для формы консоли |

### 4.3 Брокер и безопасность
- DynSec: роль на ресторан (подписка на `rf/v1/rest/{id}/broadcast`), групповые команды (BE-42).
- mTLS: CA стенда выпускает клиентские сертификаты при провижининге, ротация (BR-06, AG-13, BE-03).

### 4.4 Модель данных
`param_profiles`, `alert_rules`, `audit_log`, `restaurants.work_hours`; TimescaleDB: гипертаблицы `telemetry`, `probe_results`, `events`; retention 30 дней; continuous aggregates на 1 год.

### 4.5 Desktop-консоль
- `console/app-desktop`: окно, боковая навигация — Обзор · Инциденты · Доступность · Рестораны · Устройства · Тревоги · Профили · Правила · Отчёты · Аудит.
- Список и карточка рядом — Decompose `childPanels`; фичи из П переиспользуются без изменений `-domain/-data/-ui`.
- Новые фичи: availability (CN-11, тепловая карта), profiles (CN-12), rules (CN-13), reports + audit (CN-14).
- **Рестораны (расширение фичи `restaurants`):** таблица ресторанов + панель карточки; кнопка «Добавить ресторан» и правка на месте: код (уникальный, неизменяем после создания), название, город, адрес, часовой пояс, рабочие часы по дням недели. Валидация в domain (`CreateRestaurant`/`UpdateRestaurant` уже есть с К), ошибки показываются у поля. Доступно ролям admin и support; observer — только просмотр. Изменения пишутся в аудит. **Импорта из CSV нет.**
- QR в провижининге (CN-09 Desktop).

### 4.6 VPS
- Тот же `docker compose` (без сервиса `seed`), домен, TLS для HTTPS-бэкенда, CA стенда для MQTT/mTLS.
- Firewall: наружу только 443 и 8883; Postgres и DynSec-админка — только внутри сети compose.
- Секреты в `.env` вне git; ежедневный бэкап БД (`pg_dump` по cron); CI-деплой по тегу.
- Рестораны на VPS заводятся через Desktop-консоль.

## 7. Приёмка ВКР
