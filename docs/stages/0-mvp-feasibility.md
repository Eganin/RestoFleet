# RestoFleet — MVP: проверка осуществимости

**Цель MVP:** до начала курсовой доказать, что каждое считывание агента и каждое действие Device Owner реально работает на целевых версиях Android, а цепочка «агент → MQTT → брокер» ведёт себя как описано в протоколе. Всё, что не подтвердится, до старта курсовой переходит в ТЗ v0.3 как ограничение (⚠️) или исключение (❌).

**Этот файл — одновременно чек-лист и итоговый отчёт:** колонки результатов заполняются по ходу MVP.

Обозначения результата: ✅ работает · ⚠️ работает с ограничением (описать) · ❌ невозможно · — не применимо · ⏳ не проверено.

## Стенд проверки

Проверка идёт в два захода:
- **MVP-A — эмуляторы, сейчас.** Блокирует старт курсовой.
- **MVP-B — реальные устройства, когда они станут доступны.** Курсовую не блокирует, но должен закончиться до Д1 (Device Owner в дипломе).

| Среда | Заход | Назначение |
|---|---|---|
| Эмулятор API 26 (Android 8.0) | A | minSdk проекта, двойник планшета; нет thermal status (29+) |
| Эмулятор API 29 (Android 10) | A | thermal status, ограничения запуска из фона |
| Эмулятор API 31 (Android 12) | A | двойник телефона; ограничения запуска FGS из фона |
| Эмулятор API 33 (Android 13) | A | разрешение на уведомления |
| Эмулятор API 35 (Android 15) | A | ограничения FGS из BOOT_COMPLETED |
| Эмулятор API 36 (Android 16) | A | targetSdk проекта |
| Эмулятор актуальной версии (проверить, вышел ли API 37) | A | разрешение на доступ к локальной сети |
| Эмуляторы API 26 и 36 без аккаунтов в режиме DO | A | `adb shell dpm set-device-owner ru.restofleet.agent/.AdminReceiver` |
| **Планшет, Android 8.0 (API 26), можно сбросить** | B | реальная прошивка, датчики, батарея; **Device Owner после сброса**, HardwarePropertiesManager |
| **Телефон, Android 12 (API 31), без сброса** | B | обычный режим: thermal status и headroom, ограничения фона Android 12, прошивка вендора |
| Локальный docker compose | A | Mosquitto 2.1 (TLS + DynSec + persistence), MQTT Explorer, `mosquitto_pub/sub` |

**Что ожидаемо не проверить на реальном железе:** ограничения Android 13+ (FGS из BOOT_COMPLETED, разрешение на локальную сеть, тип FGS `specialUse`) — только на эмуляторах. **Планшет на 8.0 — полезная находка:** если на кухнях компании стоят такие же старые планшеты, thermal status там недоступен в принципе, и правило R-03 опирается только на температуру батареи. Версии Android на устройствах ресторанов уточнить в П1.

## Решение по итогам MVP

| Вывод | Действие |
|---|---|
| ✅ | требование остаётся как есть |
| ⚠️ | требование остаётся, ограничение вносится в матрицу возможностей (ТЗ 10.2) и в доменную `Capabilities` |
| ❌ | требование исключается или переносится в «Планы на развитие»; ТЗ v0.3 |
| S1 провален | симулятор переписывается на Go до курсовой |
| D1–D4 не работают на планшете | режим DO в дипломе ограничивается эмулятором, в ТЗ — явная оговорка |
| MVP-B ещё не пройден к старту Д1 | DO-функции диплома строятся по результатам эмуляторов, реальное устройство — проверка перед защитой |
