# Валидация этапа П (ПМ11)

Один проход (реш. 405; решения валидации — 510–513), локальный Docker-стенд (D14), ветка `stage/2-practice`, HEAD `10d2f68`. Сценарий — `swarm-report/practice-e2e-scenario.md`. Дефекты V-n исправляет раунд ПМ12; код в этой вехе не правился.

## Итог

**Не принято без ПМ12** (после ПМ12 — см. «Перепроверка после ПМ12»: Critical V-1…V-3 закрыты, точность второго прогона 100 %). Бэкенд и агент прошли сценарии на стенде: S8 а/б/в, S2, S3, S5, S6, S7, вход и сессии, WS через nginx с 4401. Точность классификатора по инструменту — **86,5 %, цель 90 % не достигнута**; все 13 ошибок — дефекты оценки и хранения состава инцидента (V-5, V-6), после их устранения пересчёт даёт 93,8 % и 96/96 (реш. 510). Находка 469 на стенде не воспроизвелась. Android-консоль работает через REST, но в живой среде найдены три Critical: падение обзора (V-1), WebSocket консоли не подключается ни разу (V-2), вкладки карточки устройства и статусов тревог не видны (V-3). Поэтому «обновление по WS» в консоли не проверено, а S1–S7 пройдены из консоли с обходами (перезапуск приложения, нажатие невидимых вкладок по координатам).
