## Находка 469 — результат эксперимента

`TestBroker`, Mosquitto 2.1.2, SIGTERM-рестарт, `persistence true`. Устройство подписано на `cmd/req` (QoS 1) и отключено, бэкенд публикует команду, брокер перезапускается, устройство подключается снова. Каждая ячейка прогонялась один раз.

| Первое подключение | Переподключение | `Message Expiry` | Клиент DynSec | `session present` | Доставка |
|---|---|---|---|---|---|
| Clean Start = 0 | Clean Start = 0 | есть / нет | `$CONTROL` / `mosquitto_ctrl` | 1 (4 из 4) | да (4 из 4) |
| Clean Start = 1 | Clean Start = 0 | есть / нет | `$CONTROL` / `mosquitto_ctrl` | 0 (4 из 4) | нет (4 из 4) |
| Clean Start = 0 | Clean Start = 1 | есть | `$CONTROL` | 0 | нет |
| Clean Start = 1, без рестарта | Clean Start = 0 | есть | `$CONTROL` | 1 | да |

В журнале брокера сессия, созданная с Clean Start = 1, в `Restored … clients` не попадает. Гипотеза (а) подтверждена в уточнённом виде: дело в Clean Start при создании сессии, а не только после рестарта. Гипотеза (б) — `Message Expiry` — опровергнута. Гипотеза реш. 469 про DynSec и `$CONTROL` тоже опровергнута. Агент всегда подключается с Clean Start = 0, поэтому боевой путь очередь сохраняет.
