### API для следующих вех

**`shared:protocol`** (КМ2, КМ3, КМ4):
- REST, пакет `ru.restofleet.shared.protocol.rest`: `ProvisionRequestDto(code, deviceInfo: DeviceInfoDto, agentVersion)`, `ProvisionResponseDto(deviceId, password, restaurantId, role, mqtt: MqttEndpointDto(host, port))` (`toString` маскирует пароль), `PollTelemetryRequestDto(telemetry: TelemetryDto, probe: ProbeReportDto? = null, events: List<EventDto> = [])`, `PollCommandsResponseDto(commands: List<CommandRequestDto> = [])`, `typealias PollCommandResultDto = CommandResultDto`; пути `RestPaths.PROVISION|POLL_TELEMETRY|POLL_COMMANDS|POLL_COMMAND_RESULT` (`/api/v1/...`).
- События: `ThresholdEventDto(ts, metric, state, value, limit)`, `FgChangedEventDto(ts, from?, to?)`, `FgAbsentEventDto(ts, pkg, sinceTs, limitMin, foregroundApp?)`.
- `ProbeTargetDto.expectedStatus: Int? = null`; `CommandTypes` (константы и `ALL`).
- Топики: `DeviceChannel` (`suffix`, `fromDevice`), `Topics.of(id, channel)`, `Topics.parse(topic): DeviceTopic?`, `SharedSubscriptions.of(group, channel)`, `SharedSubscriptions.backend()`.

**`shared:shadow`** (`ru.restofleet.shared.shadow`):
- `ShadowValue` (`Num(Double)` с конструкторами из `Int`/`Long`, `Str`, `Bool`, `List`, `Obj`), `ShadowDocument(fields)` (`isEmpty`, `get`, `EMPTY`), `ShadowKeys` (`VERSION`, `APPLIED_VERSION`, `APPLIED_AT`, `ERRORS`, `METADATA`).
- `delta(desired, reported): ShadowDocument`; `VersionDecision.of(stored: Long?, incoming: Long)` → `IGNORE_OLDER | ECHO_EQUAL | APPLY_NEWER`.
- `validateDesired(telemetryIntervalSec, watchedApps, probes, probeId, probeUrl): DesiredValidation<P>` (`telemetryIntervalSec: Int?`, `watchedApps`, `probes`, `errors`, `isValid`); `DesiredErrors`, `DesiredLimits` (`TELEMETRY_INTERVAL_SEC = 10..3600`, `DEFAULT_TELEMETRY_INTERVAL_SEC = 30`); `isValidPackageName`.

**`shared:probes`** (`ru.restofleet.shared.probes`):
- `ProbeErrorClass(code)` + `fromCode(code?)` (неизвестное → `OTHER`); `classifyHttpStatus(code, expected: Int? = null): ProbeErrorClass?`.
- `ProbeState(code)` `UNKNOWN|UP|DOWN`; `ProbeStateMachine(failThreshold = 3)`: `state`, `consecutiveFailures`, `onSuccess()`, `onFailure(error)`, `record(ok, error)` → `Transition(from, to, failures, error)?`.
- `ProbeSchedule(minIntervalSec = 30)`, `ProbeSchedule.forStand()` (5 с): `intervalSec(requested)`, `intervalMs(requested)`, `nextRunAt(lastRunAt?, requestedSec, now)`.

### Отклонения от плана

- Агент тронут уже в КМ1 (минимально): `ApplyDesiredShadow` вызывает `VersionDecision` и `validateDesired`, `isValidPackageName` переехал в `shared:shadow`, `ProbeError` — псевдоним `ProbeErrorClass`, `ProbeErrorClassifier.fromStatus` и `ProbeMapper` делегируют общему коду. Иначе правила жили бы в двух местах до КМ3. Тесты агента не менялись (кроме переноса `PackageNameTest` в `shared:shadow`) и зелёные.
- Сверх плана: фикстуры `beep`, `reboot`, `lock_task` (тест требует фикстуру на каждый тип из `CommandTypes`), `Topics.parse`/`SharedSubscriptions` для ingest КМ2.

### Что важно знать КМ2 (бэкенд)

- Маппер JSON ↔ `ShadowDocument` пишет `server:data`: целое число — без `.0`, `null` в JSON — как отсутствие ключа. `GET /devices/{id}/shadow` отдаёт `delta(desired, reported)`.
- `PUT /devices/{id}/shadow` может валидировать тем же `validateDesired` (коды ТЗ 7.2) — решать в КМ2; `expectedStatus` по умолчанию не задавать, пока агент не возвращает его в `reported` (КМ3).
- Нечитаемый `events` (неизвестный `type`) — ack + счётчик + лог без payload (A14).
- Статусы `queued`/`delivered`/`expired` — только в REST API, в MQTT `CommandStatusDto` их нет.

### Что важно знать КМ3 (агент)

- `run_probe{target}` и `collect_diagnostics{}` агент MVP не разбирает (ответ `unsupported` / `unknown_type`) — реализовать (FR-AG-62, 64).
- `ShadowMapper`/модель агента должны нести `expectedStatus` и возвращать его в `reported` (реш. 219); проба — `classifyHttpStatus(code, expected)`.
- `ProbeLoop` → `ProbeStateMachine` + `ProbeSchedule` (на стенде `forStand()`), `probe_state` на каждый `Transition`, включая `UNKNOWN → UP` (реш. 226).
- `EvaluateThresholds` шлёт `ThresholdEventDto` (`thermal`: код статуса, `limit` = 3), `FgChangedEventDto`, `FgAbsentEventDto` (реш. 218, 220).
- Псевдоним `ProbeError` можно убрать, перейдя на `ProbeErrorClass`.

### Что не проверено

- Совместимость нового протокола с живым агентом на эмуляторе не прогонялась (по плану ручных проверок внутри вехи нет); агент меняется только в общем коде, его unit-тесты зелёные.
- Тексты ТЗ 7.2 и 8.2 (A10, A12, A13) не правились — по плану это КМ6 (6.3).
- Ревью вехи не проводилось: одно ревью на этап после КМ4 (план).
