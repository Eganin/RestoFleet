## Отложено в этап П

Minor из ревью и валидации, которые в этом раунде не исправлялись (по одной строке):

- **R-11** — интеграционный тест ACL не проверяет запрет записи устройства в свои `shadow/desired` и `cmd/req` (главное правило P5).
- **R-12** — отмена мастера после ответа 201 теряет учётку: `persist` не под `NonCancellable`, на сервере остаётся устройство-сирота.
- **R-13** — при `NotRegistered` после сбоя Keystore экран статуса не ведёт в мастер.
- **R-14** — автомат проб, зона порога и ключ дедупликации меняются до постановки события в outbox; сбой outbox теряет переход.
- **R-15** — `ProbeLoop` при смене списка целей проверяет все цели сразу, минимальный интервал проб не соблюдается.
- **R-16** — при `ECHO_EQUAL` `reported` строится из пришедшего `desired`, а не из применённой тени.
- **R-17** — запрет редиректов и повторов для одноразового кода задан только в DI и не закреплён тестом.
- **R-18** — перцентили задержки считаются только по доставленным командам; неподключённые устройства остаются в `targets`.
- **R-19** — возобновление регистрации симулятора сдвигает раскладку ролей; сетевой сбой после погашения кода оставляет устройство без учётки.
- **R-21** — права каталогов и кэша учёток симулятора рассчитаны на macOS; учётки пишутся пачками до 64.
- **R-22** — свободная память в профилях симулятора при `timeScale = 1` не убывает (целочисленное деление).
- **R-23** — сэмплер `docker stats` и `analyze.py` молча теряют данные; у `analyze.py` нет тестов.
- **R-24** — гейт Kover `domain ≥ 90 %` на домен симулятора не действует (только модульные 80 %).
- **V-4** — переподключение агента после возврата сети ждёт текущую паузу backoff (до 120 с), `NetworkCallback` её не прерывает.
- **V-5** — мастер и экран статуса показывают UUID ресторана вместо кода и названия.

Остатки исправленных находок (тоже в П):

- **R-1/R-2** — очередь конвейера ingest (`Channel.UNLIMITED`) не ограничена для QoS 0: при недоступной БД и подключённом бэкенде живая телеметрия копится в памяти.
- **R-5** — разброс TTL кэша Basic (± 20 %) или скользящее продление: синхронный «шторм» bcrypt раз в 5 мин после массового подключения REST-парка остаётся.
- **R-7** — время ответа для неизвестного `deviceId` выдаёт, существует ли устройство (bcrypt не выполняется).
- **R-9** — повторная выдача `delivered` без итога по таймауту или подтверждение получения в REST.
- **R-3** — отладочный `DEV_CONFIG` данные прежнего устройства не стирает.
- **V-1** — отказ повторной подписки (SUBACK с ошибкой) повторяется только со следующим переподключением, не по таймеру.

## Что важно знать для перепрогона эксперимента (R-5)

- **Сценарии уже исправлены:** во всех 16 `tools/experiments/scenarios/{mqtt,rest*}-*.yaml` `durationSec: 600` (≥ 2 TTL кэша Basic, реш. 310); `smoke-*` — 30 с. `ExperimentScenariosTest` не даст вернуть окно короче 600 с и проверяет `name` = имя файла.
- **Измеритель входит заранее** (реш. 309): `prepare()` в фазе прогрева, первая команда окна — без `/auth/login`. Нужно пересобрать образ симулятора: `tools/experiments/run-experiment.sh build`.
- **Объём:** 600 команд на прогон вместо 240 (60 в минуту); каждый прогон длиннее на 6 мин, все 16 — на ≈ 1,6 ч. Access JWT (15 мин) покрывает прогрев + окно + добор, повторного входа в окне нет.
- **Обработка:** `python3 -I tools/experiments/analyze.py` берёт окно из CSV; при окне ≥ 600 с оговорки R-4/R-5 заменяются строкой «окно не короче двух TTL». Оговорка R-9 («не больше одного раза» у REST) остаётся. matplotlib в системном Python нет — графики строить из venv в scratch, как в КМ4.
- **Что пересчитать в выводах:** CPU REST при всех N (в окно теперь входят повторные bcrypt-проверки ≈ N/300 в секунду, а при N = 5 000 — и всплеск истечения кэша), «макс.» и среднее задержки MQTT (без входа). p50/p95 задержки и трафик по ожиданию не изменятся.
- **Стенд перед прогоном:** брокер с новыми пределами (`max_packet_size`, очереди 200 000 / 128 МиБ, `memory_limit` 1 ГиБ) — сообщения симулятора далеко меньше 260 КиБ; бэкенд переподписывается после рестарта брокера сам (V-1), обход реш. 296 не нужен. `RF_RATELIMIT_POLLAUTHFAILURESPERMINUTE` = 60 на IP: у REST-устройств симулятора с верными учётками 401 нет, лимит их не касается.
- **Учётки** 5 000 устройств — прежние (`deploy/out/sim/creds.jsonl`); `register` после R-20 при сбое возвращает лимит провижининга сам.
