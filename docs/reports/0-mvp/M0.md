# Отчёт вехи M0 — каркас

**Этап:** MVP-A · **Ветка:** `stage/0-mvp` · **Даты:** 06.11.2026 · **План:** `docs/superpowers/plans/2026-11-05-mvp-a.md`, задачи 0.1–0.8

## Цель вехи

Подготовить основу, которая без переделок переходит в курсовую:
- монорепозиторий Gradle без convention-плагинов;
- общий модуль ядра `shared:kernel` и черновик протокола MQTT `shared:protocol` с эталонными сообщениями;
- статический анализ, архитектурные тесты и гейт покрытия в CI;
- локальный стенд с брокером MQTT, защищённым TLS и Dynamic Security.

## Решения

См. `decisions.md`: записи 1–14 — при согласовании плана, 15–21 — по ходу M0. Главные:
- **detekt 2.0.0-alpha.6:** стабильная 1.23.8 не поддерживает Kotlin 2.4 (№ 1).
- **`Outcome`, а не `Result`:** имя не затеняет `kotlin.Result` (№ 3).
- **JUnit 4 + Truth:** тесты KMP-модулей лежат в `jvmTest`, потому что Truth работает только на JVM (№ 12).
- **Две дополнительные фикстуры и контрактный тест «канонического вида» JSON** вместо снижения порога покрытия (№ 15).
- **Свой вариант Kover `ci`** для агрегации KMP-модулей (№ 18).

## Как проверялось, что тесты что-то ловят

Тесты, написанные после кода или проверяющие конфигурацию, прогонялись против намеренно сломанного кода:

| Что сломали | Результат |
|---|---|
| `explicitNulls = true` в `RfJson` | 7 тестов протокола упали |
| Временный файл с `import android.*`, `KoinComponent`, импортом data в ViewModel и use case с двумя публичными методами | упали все 4 правила Konsist |
| Временное правило Kover «ветви ≥ 80 %» | `koverVerifyCi` упал с сообщением о нарушении |
| `allow_anonymous true` в Mosquitto | `test-stand.sh` упал на проверке отказа анонимам |

## Проблемы и как решены

1. **detekt 2 в KMP.** Задача `detekt` пустая (NO-SOURCE), анализ идёт по задачам source set'ов. В каждом KMP-модуле `detekt` сделан зависимым от них. Параметр `constructorThreshold` в detekt 2 переименован в `allowedConstructorParameters`.
2. **Truth и типы Kotlin.** Для выражений типа `Nothing?` и `Int?` перегрузки `assertThat` неоднозначны. Решено приведением к `Any?` или явно типизированной переменной.
3. **Kover и DTO.** Строки первичных конструкторов не исполняются при десериализации (она идёт через синтетический конструктор). Добавлен контрактный тест «минимальный DTO кодируется без `null`»: он и покрывает конструкторы, и защищает канонический вид JSON.
4. **Smoke-тест стенда.** Проверка таймаутом подписки не отличала «брокер отказал» от «брокер принял, но сообщений нет». Тест переписан на явный ответ CONNACK «not authorised» и проверен мутацией.
5. **Ложный «зелёный» коммит в 0.5.** Цепочка команд проверяла код возврата `grep`, а не Gradle. Найдено сразу же, исправлено отдельным коммитом; дальше коммит выполняется только при `rc == 0`.

## Отклонения от плана

- Фикстур 15, а не 13 (+ `agent_lifecycle`, `package_changed`).
- Константы `CommandStatusDto` в UPPER_CASE; на проводе — нижний регистр через `@SerialName`.
- Тесты для shell-артефактов (`test-make-ca.sh`, `test-stand.sh`) в плане не назывались — добавлены ради TDD.
- Проверка Kover-гейта на падение сделана правилом по ветвям: строки в kernel уже покрыты на 100 %, и предложенная в плане проверка не смогла бы упасть.
- Служебные скрипты `tools/dev/mark-task-done.py` и `tools/dev/handoff.py` отмечают шаги плана и обновляют handoff.

## Тезисы для текста работы

1. Сборка организована как монорепозиторий Gradle без convention-плагинов. Все версии библиотек и плагинов, а также уровни Android SDK вынесены в единый каталог `libs.versions.toml`, поэтому обновить зависимость можно изменением одной строки, а скрипт каждого модуля остаётся явным и самодостаточным.
2. Общий для агента, бэкенда и симулятора протокол обмена вынесен в мультиплатформенный модуль `shared:protocol`. Формат каждого сообщения зафиксирован эталонными JSON-примерами (golden-фикстурами). Автоматические тесты проверяют, что декодирование и повторное кодирование каждого примера дают исходный документ, — это исключает расхождение форматов между частями системы.
3. Для прямой совместимости формат толерантен к изменениям: неизвестные поля игнорируются, отсутствующие значения не передаются, а коды ошибок передаются строками. Новая версия бэкенда не ломает старые агенты.
4. Соблюдение Clean Architecture проверяется автоматически архитектурными тестами (Konsist). Доменный слой не может импортировать Android, Ktor, сериализацию или DI; у каждого сценария (use case) ровно одна публичная операция; ViewModel не обращается к слою данных напрямую.
5. Качество кода контролируется в CI тремя гейтами: статический анализ (detekt), unit-тесты и минимальное покрытие (Kover: не менее 80 % по проекту и 90 % для общих доменных модулей). На этапе M0 фактическое покрытие строк — 100 %.
6. Способность тестов обнаруживать ошибки подтверждена мутационной проверкой: намеренная порча конфигурации сериализации, архитектуры, порога покрытия и настроек брокера каждый раз приводила к падению соответствующих тестов.
7. Стенд разворачивается одной командой `docker compose`. Брокер Mosquitto 2.1 принимает подключения только по TLS на порту 8883 с сертификатом собственного удостоверяющего центра и отклоняет анонимных клиентов. Учётные записи устройств управляются плагином Dynamic Security без перезапуска брокера, а состояние сохраняется между перезапусками.
